# 感知组轨迹融合接入指南

## 1. 功能与数据流

`tracker_node` 默认保留原来的单源检测/跟踪路径。只有同时满足以下条件时才启用多源融合：

1. `enable_fusion:=true`；
2. `fusion_sources` 至少包含一个非空源名；
3. vendored `cvtrack` 可以导入并成功实例化 `TrackFusion`。

启用后，节点按每个源名订阅 `/<source>/target_track`，每 50 ms 将最新批次交给 `TrackFusion`，并把融合后的 `swarm_interfaces/TargetTrackArray` 发布到 `/target_track`。融合模式不打开本地相机，也不运行本节点内的 YOLO/tracker；各源节点必须先发布自己的轨迹。

```text
/sensor_0/target_track ─┐
                        ├─ MultiSourceAggregator ─ TrackFusion ─ /target_track
/sensor_1/target_track ─┘                 50 ms
```

## 2. 启用命令

先在 ROS2 工作空间编译并加载环境：

```bash
cd /home/hhh/Downloads/Swarm-Control-System/ros2_ws
colcon build --packages-select swarm_interfaces perception_pkg
source install/setup.bash
```

启动两源融合：

```bash
ros2 run perception_pkg tracker_node --ros-args \
    -p enable_fusion:=true \
    -p "fusion_sources:=['sensor_0','sensor_1']" \
    -p track_topic:=/target_track \
    -p frame_id:=camera_optical_frame
```

每个源需要发布对应的输入话题：

- `sensor_0` → `/sensor_0/target_track`
- `sensor_1` → `/sensor_1/target_track`

检查输入和输出：

```bash
ros2 topic echo /sensor_0/target_track
ros2 topic echo /sensor_1/target_track
ros2 topic echo /target_track
```

## 3. YAML 参数

`ros2_ws/src/perception_pkg/config/tracker_node.yaml` 的相关配置：

```yaml
/**:
  ros__parameters:
    track_topic: /target_track
    frame_id: camera_optical_frame
    enable_fusion: true
    fusion_sources: [sensor_0, sensor_1]
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enable_fusion` | `bool` | `false` | 是否启用多源融合；默认关闭以兼容单源路径 |
| `fusion_sources` | `string[]` | `[]` | 相对源名，不包含首尾 `/` 和 `target_track` |
| `sources` | `string[]` | `[]` | `fusion_sources` 为空时使用的兼容别名 |
| `track_topic` | `string` | `/target_track` | 融合或单源的统一输出 topic |
| `frame_id` | `string` | `camera_optical_frame` | 输出消息坐标系标识 |

## 4. Fallback 行为

- `enable_fusion=false`：不建立多源订阅，原本的 `input_mode=video/topic`、YOLO、tracker 和 `/target_track` 发布流程保持不变。
- `enable_fusion=true` 但 `fusion_sources=[]`：记录警告并回退到单源流程。
- `TrackFusion` 导入或实例化失败：记录错误并回退到单源流程。
- 融合启用成功后，本地检测器停止直接发布，避免与融合输出争用 `/target_track`。

## 5. 坐标与消息限制

1. **所有源必须已在同一坐标系。** 当前融合按 `TargetTrack.x/y` 做像素距离和包围框近似关联，不会自动完成相机标定、单应变换或像素到世界坐标转换。
2. **源消息不含原始包围框和 KF 协方差。** ROS 聚合器会以目标中心构造固定大小的近似框，并由置信度估算协方差；因此 ROS 路径的关联质量低于直接传递原生 `cvtrack.types.Track` 的 Python 路径。
3. **需要多个上游订阅源。** 只配置一个源可以运行，但不会获得跨传感器精度收益。
4. **输入 QoS 为 RELIABLE。** 上游源应使用兼容 QoS；QoS 不兼容时融合节点收不到轨迹。
5. **空源和超时。** 某一路发空数组时其他活跃源仍可继续输出；所有源停止更新超过 `TrackFusion.max_idle_seconds`（默认 1 秒）后对应全局轨迹会消失。
6. **全局 ID 仅在进程生命周期内稳定。** 节点重启后 ID 从头分配，不做持久化。
