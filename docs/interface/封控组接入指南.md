# 封控组接入指南

## 启动

在 ROS2 工作空间根目录执行：

```bash
cd /home/hhh/Downloads/Swarm-Control-System/ros2_ws
colcon build --packages-select swarm_interfaces containment_pkg
source install/setup.bash
ros2 run containment_pkg enclosure_node
```

可通过参数调整围控半径、最小距离和更新周期：

```bash
ros2 run containment_pkg enclosure_node --ros-args -p enclosure_radius:=25.0 -p min_dist:=5.0 -p update_period:=1.0
```

## 话题

- 输入 `/enclosure_targets`：`swarm_interfaces/msg/EnclosureTargetArray`，由感知组提供目标位置。
- 输入 `/drone_states`：`swarm_interfaces/msg/DroneStateArray`，提供模拟无人机的二维/三维位置。
- 输出 `/enclosure_command`：`swarm_interfaces/msg/EnclosureCommandArray`，描述每架无人机的目标点和有效围控半径。

## 算法说明

封装函数沿用陈思睿脚本的核心几何模型：无人机位置作为 Voronoi 生成点，围控范围用圆形区域表示。运行时节点将每架无人机分配到最近目标，并沿目标到无人机的径向方向生成围控点；半径至少满足 `min_dist`。Voronoi 基础资料见 [SciPy Voronoi 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.Voronoi.html) 和 [Wikipedia: Voronoi diagram](https://en.wikipedia.org/wiki/Voronoi_diagram)。

`static_voronoi_uav.py` 保持为原始 326 行静态演示脚本，不被节点导入或改写；`voronoi.py` 是面向 ROS 调用的脚手架，后续可继续加入真正的有限区域裁剪、Lloyd 迭代和动态重分配。

## 已知限制

- 当前接口仓库原先没有 `DroneStateArray`，本次补充了最小的 `DroneState`/`DroneStateArray` 定义；若调度组已有正式版本，应统一字段后移除重复定义。
- 目标坐标被视为与无人机相同的二维平面坐标，不包含 GPS 或坐标系转换。
- 目标数量少于无人机数量时，按状态数组顺序将多余无人机置为待命，命令坐标为 NaN。
- 原始脚本的绘图、覆盖率统计和 Shapely 任务区域裁剪仍是离线演示逻辑，未放入实时节点。
