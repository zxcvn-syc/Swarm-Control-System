# D-1 至 D-12 接口决议归档

> 责任人：何泓林
> 生效范围：`three_links.launch.py`、感知/规划/封控节点、PX4 SITL 桥接与 CI。
> 本归档与 `docs/integration/interface_alignment.md` 一并维护；本文补充已落地的真实规划与 SITL 约束。

| 决议 | 最终约定 | 代码落点 |
|---|---|---|
| D-1 时间戳 | 感知优先使用最新 `/drone_states` 的 `header.stamp`；未收到状态时保留图像源时间戳或本地时钟。 | `perception_pkg/tracker_node.py` |
| D-2 坐标系 | 像素轨迹使用 `camera_optical_frame`；`/target_track_world`、`/drone_states`、`/drone_pose_external` 使用局部 ENU 米制 `world`。 | `coord_transform_node.py`、`planner_node.py` |
| D-3 任务分配 | `TaskAssignment` 只传递 `drone_id`、`target_id` 与任务类型；规划节点从世界坐标轨迹取得目标位置。 | `scheduler_node.py`、`planner_node.py` |
| D-4 规划接入 | 正式 `planner_node` 输出 `/planned_path` 和 `/drone_states`；不再以 `planner_stub` 作为主链路。 | `three_links.launch.py`、`planning_pkg` |
| D-5 QoS | 控制与状态契约默认 `RELIABLE depth=10`；原始图像与 MAVROS 位姿订阅使用传感器 QoS，保证与 BEST_EFFORT 发布者匹配。 | `rflysim_follower.py`、`sitl_pose_bridge.py` |
| D-6 封控输入 | `tracker_node` 发布 `/enclosure_targets`，封控节点消费它和 `/drone_states`。 | `tracker_node.py`、`enclosure_node.py` |
| D-7 兼容输入 | 封控节点保留 `/target_track` 兼容订阅，迁移时以后到消息为准。 | `enclosure_node.py` |
| D-8 同步方式 | 上游定时重发最新全量快照；下游不得假设 latch 存在。 | 各节点 timer / subscription |
| D-9 空闲态 | 无目标发布空命令；多余平台使用 NaN 目标点和零半径待命命令。 | `enclosure_node.py` |
| D-10 容错 | 节点应允许上游尚未出现；SITL launch 缺 PX4 构建时快速失败并保留日志。 | `sitl_test.launch.py` |
| D-11 资源隔离 | YOLO/Re-ID 权重为外部资源；CI 不声明推理权重已验证，使用合成输入或单元测试覆盖接口。 | `test_three_links.py`、感知测试 |
| D-12 命名空间 | 系统业务话题保留 root 命名空间；外部 MAVROS 使用 `/uav0`，其位姿被桥接回根话题 `/drone_pose_external`。 | `px4_sitl.launch.py` |
