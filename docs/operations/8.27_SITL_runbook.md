# 8.27 封控测试操作手册（交接版）

> 适用：何泓林在 VM/WSL 上独立跑 headless / SITL 两条冒烟链路与批量测试。
> 依赖：ROS2 Humble、仓库已 clone、SITL 环境（`simulation/px4_sitl_3uav/start_3uav_sitl.sh`）可用。

---

## 一、编译

```bash
cd <仓库根>
source /opt/ros/humble/setup.bash
colcon build --packages-select containment_pkg swarm_interfaces
source install/setup.bash
```

**成功标志**：
- `ros2 pkg prefix containment_pkg` 能输出路径。
- `ros2 launch containment_pkg <按 Tab 两下>` 能补出 launch 文件名。

---

## 二、冒烟链路①：headless（判定逻辑自洽，mock 平台）

目的：验证工具链本身能跑，能出 SUCCESS/FAIL/INVALID 三种判定。

```bash
cd <仓库根>
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash

ros2 launch containment_pkg escape_eval.launch.py scene:=park direction:=2 trajectory:=return result_csv:=/tmp/smoke1.csv
```

**正常标志**（终端约 10s 内出现）：
```text
[containment_evaluator-4]: [VERDICT] scene=park dir=2 traj=return -> SUCCESS (re_contained) max_r=... min_platform_dist=1.48 responded=5
```

`/tmp/smoke1.csv` 多出一行数据即算通过。

> 这步只证明工具链能跑，**不代表 8.27 SITL 真位姿链路通了**。

---

## 三、冒烟链路②：SITL 真位姿对接（关键，验 8.27 可行性）

> 拓扑说明：SITL 平台层由 `sitl_state_publisher.py` **直接往 `/drone_states` 发 3 真 UAV + 2 mock UGV**（不是 `/drone_pose_external`）。`escape_eval_sitl.launch.py` 默认 `platform_source:=external`，即**不自己起平台节点**，直接吃外部 `/drone_states`。所以下面三步缺一不可。

### 3.1 起 SITL 三机仿真（PX4 ×3 + Gazebo）

在终端 A 执行（不要关）：

```bash
./simulation/px4_sitl_3uav/start_3uav_sitl.sh
```

### 3.2 起平台层（mavros ×3 + sitl_state_publisher → /drone_states）

在终端 B 执行（不要关）。这一步**只起平台，不起 enclosure_node**：

```bash
bash simulation/px4_sitl_3uav/start_sitl_platform.sh
```

### 3.3 确认真位姿已进来

在终端 C：

```bash
ros2 topic echo /drone_states --once
```

应看到 5 个平台（3 个 UAV 真位姿 + 2 个 UGV，UAV 的 `available:true`）。如果为空或 UAV `available:false`，先查 `/tmp/mavros_uav*.log` 是否 `CON: Got HEARTBEAT`。

### 3.4 跑 SITL 版测试

```bash
cd <仓库根>
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch containment_pkg escape_eval_sitl.launch.py scene:=park direction:=2 result_csv:=/tmp/smoke2.csv
```

**验收标准**：
- evaluator 出判定且 `/tmp/smoke2.csv` 有数据。
- 若出 `INVALID`（no_response_evidence），说明 `/drone_states` 没进到判定器或平台距目标始终 >5m——先 `ros2 topic echo /drone_states --once` 确认位姿在流。
- 注意：纯 SITL 位姿下 UAV 不会自动飞去拦截（mavros 未 ARM/发 setpoint），UGV 在 15m 圆周。若目标直冲 25m 外会判 `FAIL`；要让平台真正 ≤5m 需接 offboard 控制链（px4_sitl.launch.py + auto_arm）。**SITL 冒烟的意义是验证“真位姿能驱动判定器跑通”，不是复现 headless 的 89.8% SUCCESS。**

**两条冒烟都出合理结果，才算“部署完成”。只过 Step ① 不算数。**

## 四、批量测试

### 4.1 mock 批量（陈思睿 8.28 出统计表用）

```bash
cd <仓库根>
bash run_batch.sh
```

- 60 次，约 42 分钟。
- 产出：`docs/evidence/eval_results_YYYY-MM-DD.csv` + `*_summary.md`。

### 4.2 SITL 批量（何泓林 8.27 用，默认 30 次）

要求 SITL 环境已起，且冒烟链路②通过。

```bash
cd <仓库根>
bash run_batch_sitl.sh
```

- 默认 10 次/场景，共 30 次；要跑满 60 次用：
  ```bash
  RUNS_PER_SCENE=20 bash run_batch_sitl.sh
  ```
- 产出：`docs/evidence/eval_results_sitl_YYYY-MM-DD.csv` + `*_summary.md`。

> `run_batch_sitl.sh` **只杀测试节点**，不杀 SITL/PX4/Gazebo；跑完 SITL 环境还在，可继续下一轮或手动关闭。

## 五、怎么看结果

### 5.1 实时监控

```bash
# 看当前批量日志
tail -f /tmp/batch_YYYY-MM-DD.log

# 看已判多少行（CSV 含表头，行数-1=已判次数）
wc -l docs/evidence/eval_results_YYYY-MM-DD.csv

# 看最近几条判定
grep VERDICT /tmp/batch_YYYY-MM-DD.log | tail -5
```

### 5.2 结果含义

`outcome` 列：
- `SUCCESS`：目标被回收/守住，且曾有平台距目标 ≤5m（有响应证据）。
- `FAIL`：目标突破 monitor_radius（25m）。
- `INVALID`：目标被回收，但全程无平台进入 5m，不能算系统功劳；**单列、不计入成功率**。

`summary.md` 里的“封控成功率” = `SUCCESS / (SUCCESS + FAIL)`，目标 ≥85%。

## 六、常见失败长什么样

| 现象 | 原因 | 处理 |
|------|------|------|
| evaluator 出 `INVALID`（SITL 模式） | `/drone_states` 没数据，或平台距目标始终 >5m | 先 `ros2 topic echo /drone_states --once` 确认位姿在流；查 `/tmp/sitl_state_pub.log` |
| `ros2 topic echo /drone_states` 为空 | 没跑 3.2 的 `start_sitl_platform.sh`，或 mavros 没连上 PX4 | 查 `/tmp/mavros_uav*.log` 有无 `CON: Got HEARTBEAT` |
| 起 launch 报 `enclosure_node` 已存在 | 同时跑了 `start_3uav_ros.sh`（它自带 enclosure_node） | SITL 测试只用 `start_sitl_platform.sh`（不起 enclosure_node），别用 `start_3uav_ros.sh` |
| 所有 run 都是 `SUCCESS` 且 min_platform_dist 一样 | 跑的还是 mock，不是 SITL | 检查是不是用了 `escape_eval.launch.py` 而不是 `escape_eval_sitl.launch.py` |
| mock 批量出现大量 `INVALID` | mock 平台轨道半径过大或角速度太快，没采到近点 | 检查 launch 里的 `monitor_orbit/block_orbit`（默认 16/15）和 `phase_step` |
| `run_batch*.sh` 里 `result_csv` 路径写死到别人机器 | 本仓库已用 `BASH_SOURCE` 相对路径，克隆到任意位置都能跑 | 不要再写绝对路径 |
