# SCS 车侧四关自动测试 — 使用说明

部署位置：
- 主机（pi 用户）：`~/scs_autotest.sh`（安全壳，已 chmod +x）
- 容器（ubuntu）：`/home/ubuntu/scs_autotest_driver.py`（rclpy 驱动，docker cp 部署）

本地副本：本目录 `scs_autotest.sh` / `scs_autotest_driver.py`

## 用法（在车旁电脑 SSH 到车后执行，或由我远程执行）

| 命令 | 作用 |
|---|---|
| `bash ~/scs_autotest.sh` | 只打印说明，**什么都不做**（默认安全） |
| `bash ~/scs_autotest.sh --dry-run` | 预览各关规划，不碰 ROS，车不会动 |
| `bash ~/scs_autotest.sh --run straight` | 第1关 直线 1.5m |
| `bash ~/scs_autotest.sh --run turn` | 第2关 90° 转弯（L形：直行0.8m→右转走0.8m） |
| `bash ~/scs_autotest.sh --run retarget` | 第3关 动态换目标（走一半切目标） |
| `bash ~/scs_autotest.sh --run estop` | 第4关 急停（行进中强制停，测3s漂移） |
| `bash ~/scs_autotest.sh --run full` | 连跑四关，任一关失败中止 |

## 安全机制（为什么可以放心传上车）

1. **默认是"死"的**：无自启、无 cron、无 watchdog。只有人敲 `--run xxx` 才会动。
2. **电量闸门**：`--run` 前自动读电池，< 7500mV 直接拒跑（9.2 实测 7315mV 时电机已被低压保护切断力矩，故留余量）。
3. **5 秒倒计时**：开始前倒数 5 秒，可 Ctrl+C 取消。
4. **路径超时兜底**：一旦驱动进程被杀（Ctrl+C / 崩溃），follower 2 秒收不到路径自动零速停车 —— 不需要额外急停命令。
5. **驱动内超时急停**：每关超过最长时限自动发"当前位置点"路径强制停。
6. **急停算法**：持续发"最新位姿点"路径，follower 每周期看到目标在脚下即判 DONE 零速；点随车滑行刷新，不会追旧点转圈。
7. **运行中电压看门狗（9.3 加）**：跑动过程中驱动实时读电池，≤7300mV 立即急停并明确报"低压保护触发"（而不是干耗到超时）；<7500mV 每 10s 告警一次。

## 运行前提

1. 已跑 `bash ~/scs_start.sh` 开场（厂商栈 + relay 就绪，/odom 与 /ugv_pose 约 30Hz）
2. follower 缺省会自动拉起（壳检查进程）
3. **车头朝正东**摆好、场地净空（各关最近需前方 2.5m、右侧 0.9m）
4. 电池 ≥ 7500mV
5. 车落地、轮子着地、周围无人无物

## 判关注意（9.2 实测后必读）

`/ugv_pose` 来自厂商 odom_publisher 的 **cmd_vel 数值积分**（不读编码器）——
电机被切断/车没动时 odom 照样"前进"。因此：

- 驱动打印的 odom 位移、用时、电池最低只作**证据**；
- **判关必须核对物理位移（录像/目测）**，不能只信 odom；
- 每关结束驱动会打印小结行，配合录像人工裁定该关 PASS/FAIL。

## 各关行为

- **直线**：沿车头方向 1.5m，follower 到点自停，超时 40s
- **转弯**：L 形两段（0.8m 直 + 右转 90° 走 0.8m），差速小弧转弯，超时 60s
- **动态换目标**：先发正前 1.0m 目标等车动 ≥0.2m，改发右侧 0.9m 新目标，验证 follower 路径切换，超时 40s
- **急停**：发正前 2.5m 让车行进 ≥0.4m，触发急停后静置 3s 测漂移，≤0.05m 判通过，超时 40s

## 退出码

- 0 = 全部通过；2 = 有关卡失败；1 = 前置检查拒绝（电量不足/读不到电池）
