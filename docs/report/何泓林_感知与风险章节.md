# 感知跟踪与风险章节供稿

## 第四章：感知、坐标转换与态势感知

系统以 YOLOv8 目标检测和 DeepSORT 轨迹管理为感知入口。检测结果经过卡尔曼滤波、轨迹预测和运动模式判别后，被封装为 `TargetTrackArray`；其中目标 ID、位置、速度、置信度、确认状态和预测序列可被调度、规划和封控模块复用。对于多摄像头或多传感器输入，`TrackFusion` 按来源维护轨迹并对同一目标进行置信度加权融合，从而避免单一视角短时遮挡直接造成目标丢失。

像素轨迹与平台决策之间通过 `coord_transform_node` 解耦。节点利用相机内参、机体姿态与地面平面交点，将 `camera_optical_frame` 下的像素观测转换为 `world` ENU 坐标；保留原始像素话题用于跟踪调试，并将世界坐标话题提供给路径规划。感知节点订阅最新平台状态，并将可用的状态时间戳写入输出头部，使态势数据与空地平台状态能够按同一时间基准进行新鲜度判断。

态势感知由 `/target_track`、`/target_track_world`、`/drone_states` 和 `/enclosure_command` 的一致接口实现。调度模块依据目标风险和平台可用性生成任务，规划模块产生路径，封控模块根据目标与平台状态形成围控命令。该分层设计使检测模型、坐标模型和决策模型可独立替换，同时保持 ROS2 Topic 契约不变。

## 第七章：风险与安全

仿真与真机控制采用分级验证。第一层为 Python/ROS2 单元与端到端话题测试；第二层为 PX4 SITL、Gazebo 与 MAVROS 桥接；第三层才是受监管的实机验证。任何层级的缺失均不应以更高层级结果替代或宣传。当前项目已提供单 UAV 可复现 SITL 启动、超时 watchdog、路径到 offboard setpoint 的桥接和位姿回传链路；Gazebo/MAVROS/PX4 安装完成后，必须保留启动日志、话题采样、内存曲线及录像原始文件。

两小时连续运行使用 `scripts/run_soak_test.sh --duration 7200` 自动采集节点数量、主启动进程 RSS、日志与 JSON 结果。验收条件为：启动进程在请求窗口内未提前退出，CSV 无异常中断，报告状态为 `PASS`。若出现失败，报告中的 `failure_reason`、日志末尾与最后一条 CSV 样本共同构成故障复现证据。真机飞行属于加分验证，未取得硬件、场地和飞控日志前仅列为后续工作。

本次 Ubuntu 22.04 ROS 2 Humble VM 验证已完成单机 PX4 v1.14、Gazebo Classic 11.10.2、MAVROS smoke，并在 `ROS_DOMAIN_ID=60` 下完成三链路八节点 headless 连续运行。浸泡报告记录 `PASS`，请求时长 7200 秒、实际 7256 秒；启动宽限期后的 115 条样本均为 8/8 节点在线，主启动进程 RSS 为 36,712-36,720 KB，日志未出现 traceback、节点提前退出或错误模式。原始 JSON、CSV、日志和 SHA-256 校验值见 `docs/evidence/three_links_soak_20260820.md`。该结果证明 ROS2 集成栈的连续运行稳定性，不宣称车辆解锁、Offboard 飞行、真机飞行或桌面全系统 MP4 已完成。
